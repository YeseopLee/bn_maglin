# 메글린PRD

**2D 게임 (유니티 기반) Product Requirements Document**

# 📖 Ⅰ. 개요 및 게임 콘셉트

---

### 📌 1. 게임 이름

- **메글린(Maglin)** *(가제)*

---

### 📌 2. 장르 및 스타일

- **장르:** 덱빌딩 카드 배틀
- **서브 장르:** 로그라이크
- **그래픽 스타일:**
    - 횡스크롤 방식의 2D 게임
    - 일러스트 중심의 캐릭터와 몬스터 디자인
    - 카드 사용 시 직관적이고 화려한 이펙트 연출
- **게임 분위기:**
    - 전략성과 깊이를 강조한 플레이 스타일
    - 로그라이크 특유의 긴장감과 반복 플레이 시의 발전 요소 강조

---

### 📌 3. 주요 특징 및 차별점

- **로그라이크 시스템**
    - 플레이어가 사망하면 모든 진행상황을 잃고 다시 처음부터 플레이해야 하는 하드코어 스타일 게임
    - 매 회차마다 랜덤으로 등장하는 다양한 몬스터와 이벤트 구성으로 높은 리플레이성 확보
- **독특한 카드 조합 메커니즘**
    - 기본 카드 사용 외에, 최대 3장의 카드를 조합하여 새로운 효과와 능력을 발휘하는 독창적인 시스템
    - 특정 조합이 아닌 무작위 카드 조합은 오히려 페널티를 부여하여 전략적 선택의 중요성을 강조
- **속성과 필드 시스템을 활용한 전략적 깊이**
    - 필드 속성 부여를 통해 카드의 효과가 다채롭게 변화하여 깊이 있는 전략 제공
    - 5가지의 속성(불, 물, 풀, 빛, 어둠)을 활용한 속성 상성 시스템으로 플레이어의 전략적 판단력을 자극
- **몬스터와 플레이어의 위치기반 전투 시스템**
    - 10칸으로 나누어진 횡스크롤 필드에서 몬스터의 이동 패턴과 공격 거리를 활용한 전략 전투
    - 보스 몬스터의 다양한 기믹 패턴과 강제 카드 삽입 등 독창적 전투 요소 제공
- **유물 시스템을 통한 성장과 다양한 플레이 경험**
    - 획득할 때마다 회차 내 영구적인 효과를 얻을 수 있는 유물 시스템 도입
    - 유물 획득 전략을 통해 플레이어가 전투와 덱 운영을 능동적으로 조정 가능

### 📌 5. 게임 진행 방식 (로그라이크 요소 설명)

**기본 진행 흐름:**

- 플레이어는 1층부터 시작하여 탑을 오르는 형태로 진행
- 층마다 전투, 상점, 이벤트 중 하나를 플레이하게 됨
- 각 층에서 승리 시 다음 층으로 이동하며, 10층 단위로 보스전 진행
- 패배하면 지금까지의 모든 진행사항을 잃고 처음부터 다시 시작

**층 구성 및 구조:**

| 층 번호 | 층의 성격 | 비고 |
| --- | --- | --- |
| 일반층 | 일반 몬스터 전투 | 층마다 랜덤 배틀 |
| 엘리트층 | 특별한 보상과 어려운 전투 | 5층, 15층, 25층 등 5층 단위 등장 |
| 상점층 | 상점 (카드/유물 구매, 회복) | 3층마다 등장 (예: 3.5층, 6.5층, 9.5층 등) |
| 보스층 | 강력한 보스 몬스터와의 전투 | 10층 단위 (10층, 20층 등) |
| 이벤트층 | 특수 이벤트 | 특정 조건이나 랜덤한 기회로 등장 가능 (선택사항) |

---

### 📌 6. 게임 플레이 주요 목표

- 플레이어는 매 회차 다양한 카드 및 유물을 전략적으로 조합하여 최대한 높은 층까지 도달하는 것이 목표
- 반복 플레이를 통해 더욱 다양한 카드와 유물을 해금하고 전략을 다듬으며 높은 층에 도전하는 재미 제공
- 각 층의 랜덤 배틀 및 이벤트는 항상 신선한 경험을 주어 게임의 장기적인 플레이 유도

---

### 📌 7. 대상 사용자층

- 카드 배틀과 전략적 사고를 즐기는 유저층
- 도전적인 로그라이크 게임 플레이를 선호하는 유저층
- 반복 플레이를 통한 성장과 전략 최적화에 매력을 느끼는 게이머층
- 슬레이 더 스파이어(Slay the Spire), 몬스터 트레인(Monster Train) 등 유사한 장르를 좋아하는 사용자층

# 🎮 Ⅱ. 게임 시스템 구조

『메글린』은 아래와 같은 직관적이고 명확한 게임 시스템 구조로 설계됩니다.

---

### 📌 1. 전체 게임 플로우 (진행 구조)

- **시작점**
    
    플레이어는 **1층에서 시작**하며 탑을 오릅니다.
    
- **진행 방식**
    
    각 층 진입과 동시에 **즉시 전투 또는 이벤트가 시작**됩니다.
    
    별도의 버튼을 누를 필요 없이, 전투 종료 시 보상 획득을 진행하고, 다음 층으로 이동합니다.
    
- **종료 조건**
    
    플레이어가 패배하여 체력이 0이 되면, 모든 진행 상황을 잃고 다시 1층부터 시작합니다.
    

---

### 📌 2. 메인 화면 및 UI 구조

메인 UI 화면은 플레이어가 전투 및 게임 상태를 쉽게 파악할 수 있도록 구성됩니다.

| UI 요소 | 상세 설명 |
| --- | --- |
| 플레이어 상태 UI | 체력(HP), 마나(MP), 골드, 유물 현황 표시 |
| 카드 덱 UI | 현재 덱의 카드 목록 및 보유 카드 관리 |
| 카드 드로우 UI | 현재 턴에 보유한 카드 표시 |
| 카드 사용 공간 | 카드 3장을 배치 및 조합 후 사용 |
| 사용 버튼 | 카드 사용 확정 버튼 (턴 종료와 별개) |
| 턴 종료 버튼 | 플레이어 턴 종료 및 몬스터 턴으로 전환 |
| 필드효과 표시 | 현재 필드의 속성 아이콘, 배경 색상 변화 등 |
| 선택 대상 마커 | 공격 대상으로 지정된 몬스터 표시 |
| 설정 메뉴 | 옵션, 사운드 조절 등 설정 관리 |

---

### 📌 3. 주요 화면 설명

게임의 주요 화면은 아래의 3가지로 구성됩니다.

### [1] 전투화면

- 10칸의 횡스크롤 필드 구조를 가지며, 플레이어와 몬스터가 위치합니다.
- 플레이어는 왼쪽 끝(1번칸)에 고정되어 있습니다.
- 몬스터는 항상 오른쪽 끝에서 등장하며, 여러 마리 등장 시 오른쪽에서부터 한 칸씩 밀려서 등장합니다.
- **여러 칸을 차지하는 몬스터**(보스 등)는 다른 몬스터와 절대 겹치지 않도록 미리 계산하여 등장합니다.

| 칸 번호 | 위치 구조(예시) |
| --- | --- |
| 1번칸 | 플레이어(고정) |
| 2번칸 | 비어있음(초기 상태) |
| ... | 비어있음 |
| 8번칸 | 몬스터(여러 마리 시) |
| 9번칸 | 몬스터 |
| 10번칸 | 몬스터(오른쪽 끝에서 등장 시작) |
- 전투 종료 시 보상 획득을 진행하고 다음 층으로 이동합니다.

---

### [2] 상점화면

- **3층마다 (3.5층, 6.5층, 9.5층 등)** 등장하는 특수한 층입니다.
- 획득한 골드를 소비하여 덱을 강화하거나 체력을 회복합니다.
- 보스 유물은 등장하지 않으며, 모든 구매 행위에 일정량의 골드가 소모됩니다.

| 판매 항목 | 설명 | 골드 소모 여부 |
| --- | --- | --- |
| 카드 구매 | 랜덤하게 제시된 카드를 구매 | ✅(골드 소모) |
| 카드 제거 | 덱에서 카드 1장을 영구히 제거 | ✅(골드 소모) |
| 유물 구매 | 일반 유물을 구매 | ✅(골드 소모) |
| 체력 회복 | 일정 체력 회복 | ✅(골드 소모) |

---

### [3] 이벤트화면

- 이벤트는 **랜덤**으로 등장하며, 원래 전투가 진행될 층에서 대신 발생합니다.
    - 예를 들어 원래 2층이 일반 전투였으나, 랜덤 확률로 이벤트로 변경될 수 있습니다.
- 이벤트는 다양한 선택지를 제공하여, 덱 강화, 유물 획득, 추가 골드 등 여러 보상을 제공합니다.
- 선택에 따라 리스크(체력 감소, 카드 제거 등)가 있을 수 있습니다.
- 현 이벤트 화면을 설명할 textarea와 선택지가 존재합니다.

| 이벤트 예시 | 보상 예시 | 리스크 예시 |
| --- | --- | --- |
| 의문의 제단 (선택지 제공) | 강력한 카드 얻기 | 카드 한 장 강제 삭제 |
| 떠돌이 상인 | 저렴한 가격의 랜덤 유물 구매 | 소량의 체력 소모 |
| 함정에 빠진 모험가 | 골드나 카드 제공 | 일정 체력 소모 |

---

### 📌 4. 층 구조 설명

게임 진행 층 구조는 다음과 같습니다.

| 층 유형 | 등장 규칙 | 상세 설명 |
| --- | --- | --- |
| 일반층 | 기본적으로 매 층마다 등장 | 기본적인 몬스터 전투 진행 |
| 엘리트층 | 5층 단위로 등장(5,15,25층 등) | 강력한 몬스터와 전투, 유물 보상 |
| 상점층 | 3층 단위(3.5,6.5,9.5층 등) | 골드를 소모하여 카드/유물/회복 |
| 보스층 | 10층 단위(10,20,30층 등) | 특별한 패턴의 강력한 보스와 전투 |
| 이벤트층 | 랜덤 확률로 일반 전투층 대체 | 선택 기반 이벤트 진행(리스크有) |

---

### 📌 5. 플레이 루프 흐름 예시

게임은 별도의 층 진입 버튼 없이 즉시 진행됩니다.

**예시 플로우:**

```

1층(일반 전투 or 이벤트) → 2층(일반 전투 or 이벤트) → 3층(일반 전투 or 이벤트)
→ 3.5층(상점) → 4층(일반 전투 or 이벤트) → 5층(엘리트 전투)
→ 6층(일반 전투 or 이벤트) → 6.5층(상점) → 7층(일반 전투 or 이벤트)
→ 8층(일반 전투 or 이벤트) → 9층(일반 전투 or 이벤트) → 9.5층(상점)
→ 10층(보스 전투) → 보스 클리어 시 보상 및 상점 자동 진입 → 11층(다음 일반 전투로 즉시 진행)
```

- 전투 및 이벤트 종료 시 별도의 화면 전환 버튼 없이 즉시 다음 층으로 자동 진행됩니다.

# 🃏 Ⅲ. 카드 시스템 상세 정의

『메글린』의 핵심인 카드 시스템은 명확한 규칙과 관리 구조로 플레이어가 전략적으로 활용할 수 있도록 구성됩니다.

---

### 📌 1. 카드 종류 및 기본 규칙

### (1) 카드 기본 유형

- 카드의 종류는 크게 다음 4가지로 구분됩니다.

| 카드 유형 | 단독 사용 가능 여부 | 설명 | 예시 |
| --- | --- | --- | --- |
| 속성 카드 | ❌(불가능) | 다른 카드와 반드시 조합하여 사용 | [불], [물], [풀], [빛], [어둠] |
| 액티브1 카드 | ✅(가능) | 단독 혹은 다른 카드와 조합하여 사용 | [에너지볼], [베기] 등 |
| 액티브2 카드 | ✅(가능) | 단독 혹은 다른 카드와 조합하여 사용 | [강타], [폭발] 등 |
| 조합 카드 | ❌(불가능) | 다른 카드들로 조합됨으로써만 사용 | [파이어볼 (불 속성 + 에너지 볼)] 등 |

조합 카드는 속성/액티브1/액티브2와 달리 반드시 어떤 카드들의 조합으로만 사용되는 카드이므로, 상점에서 판매된다거나 전투 보상으로 등장하지 않는다.

---

### (2) 속성 카드의 상성 규칙

| 속성 | 강한 속성(상성 효과) | 약한 속성(역상성 효과) | 비고 |
| --- | --- | --- | --- |
| 불 | 풀 | 물 |  |
| 물 | 불 | 풀 |  |
| 풀 | 물 | 불 |  |
| 빛 | 어둠 | 어둠 | 서로 1.2배 데미지 |
| 어둠 | 빛 | 빛 | 서로 1.2배 데미지 |
- 속성 상성 효과로 데미지 증감이 이루어지며, 플레이어는 적의 속성을 고려하여 전략을 짤 수 있습니다.

---

### 📌 2. 카드 조합 시스템 (핵심 규칙)

### (1) 조합 규칙

- 카드는 **최대 3장까지** 조합하여 사용할 수 있습니다.
- **같은 종류의 카드끼리는 조합할 수 없습니다**.
    - (속성+속성, 액티브1+액티브1 조합은 불가능)
- **허용되는 조합 예시**:

```

① [액티브1] (단독사용 가능)
② [액티브2] (단독사용 가능)
③ [속성] + [액티브1]
④ [속성] + [액티브2]
⑤ [액티브1] + [액티브2]
⑥ [속성] + [액티브1] + [액티브2]
```

### (2) 조합 결과 효과

- 카드 조합에 따라 **사전에 정의된 새로운 카드로 변경**되어 발동됩니다.
- 카드 조합에는 카드끼리만 조합될수도, 현재 필드효과도 필요한 조합식도 존재한다.
- **예시**:

```

[불]+[에너지볼] 조합 → [파이어볼]로 발동 (불 속성 데미지)

현재필드가 불 필드일때: [불] + [에너지볼] 조합 → [메테오]로 발동
```

- 정의되지 않은 조합을 사용 시 **페널티 또는 무효화 또는 일부시전 또는 무작위 카드 시전** 됩니다.
    - 스킬 발동 안함, 하나의 스킬만 발동, 사용자 피해, 아예 상관없는 게임내의 별개의 랜덤한 카드 효과 발동
    - 일반적으로 잘못된 조합 사용시 위 네가지중 랜덤으로 발생하지만 (각각의 확률은 개발단계에서 조정), 특정 카드에 미리 정의된 강제효과에 따라 반드시 발생하는 패널티 효과가 있을 수 있음.
    - 예를들어 “나에게 5의 피해를 준다”라는 “자해”라는 카드는 단독사용 및 잘못된 조합 사용시, 위의 **페널티 또는 무효화 또는 일부시전 또는 무작위 카드 시전** 대신 반드시 이 스킬만 발동하는 효과로 적용 됨.

---

### 📌 3. 필드 속성에 따른 카드 효과 변화

### (1) 필드 속성 시스템

- 특정 카드는 전투 중 **현재 필드에 특정 속성을 부여**할 수 있습니다.
- 필드 속성은 아이콘으로 맵에 별도로 표시되며, 전투필드 배경색도 속성에 따라 바뀝니다.
- 필드 속성에 따라 카드 조합 효과가 변동될 수 있습니다.

| 필드 속성 상태 | 카드 조합 예시 | 기본 효과 | 필드효과로 인한 변화 |
| --- | --- | --- | --- |
| 불속성 필드 | [불]+[에너지볼]+[폭발] | A 카드 발동 | A카드가 강화되거나 B 카드가 발동 |
| 물속성 필드 | [물]+[베기]+[강타] | C 카드 발동 | C카드가 강화되거나 D 카드가 발동 |
- 모든 효과 변경 및 강화는 랜덤이 아니며 **개발 단계에서 명시적으로 사전 설정됩니다**.

---

### 📌 4. 카드 사용 방법 및 대상 지정 방식

### (1) 카드 사용 인터페이스

- 화면 하단에 **3개의 빈 카드 슬롯**이 존재합니다.
- 원하는 카드(최대 3장)를 슬롯에 배치한 후, **「사용」 버튼**을 클릭하면 카드 효과가 발동됩니다.
- 「사용」 버튼 클릭 후에도 턴 종료는 되지 않으며, 여러 번 카드 사용 가능합니다.
- 카드 사용에는 별도의 마나가 소모되지 않습니다.

### (2) 대상 지정 규칙

- 대상은 몬스터 클릭이나 Tab키로 변경 가능합니다.
- 카드 사용 시 대상 지정은 다음 중 하나로 설정됩니다.
    - 적 1인
    - 본인(플레이어)
    - 적 전체
    - 나 포함 적 전체
    - 앞의 N명, 뒤의 N명 등 범위 공격
- 본인 대상 카드는 대상 선택과 별개로 오직 플레이어 자신에게만 시전됩니다.

### 📌 7. 카드 조합식 관리 시스템

『메글린』의 핵심인 **카드 조합 시스템**은 다양한 카드 효과의 조합과, 그에 따른 새로운 결과 스킬 생성, 실패 시 효과 처리까지 포함하는 정교한 구조로 설계됩니다.

---

### (1) 조합식 존재 여부 판단 로직

**조합 가능한 형태**

사용자는 아래 4가지 방식으로 카드를 조합할 수 있습니다:

| 조합 형태 |
| --- |
| `속성 + 액티브1` |
| `속성 + 액티브2` |
| `액티브1 + 액티브2` |
| `속성 + 액티브1 + 액티브2` |
- **동일한 종류의 카드는 함께 조합할 수 없습니다.**
    - 예: 액티브1 + 액티브1 → 불가능
    - 속성 + 속성 → 불가능
- 특정 카드는 조합에 현재 필드효과의 유무도 판단합니다.
    - 예: 필드효과 없을때 불속성카드 + 에너지볼카드 = 파이어볼 카드 발동
    - 예: 불 필드효과 있을때 불속성카드 + 에너지볼카드 = 메테오 카드 발동

### 📌 인게임 조합 처리 로직

- 플레이어가 카드들을 조합 슬롯에 배치하면, 다음과 같은 로직이 수행됨:

### 구조 요약

- 각 카드(`CardSO`)는 **"자신이 어떤 조합식의 결과물인지"**를 알고 있음
- 예를 들어, `파이어볼` 카드라면
    
    ```csharp
    
    class CardSO {
        string id = "fireball";
        CardCombination[] combinations = [
            { element: "불", active1: "에너지볼", active2: null, field: "불" }
        ];
    }
    ```
    
- 사용자가 "불 + 에너지볼"을 조합했을 때:
    1. **전체 CardSO를 탐색**
    2. 각 카드의 `combinations` 중 **현재 조합과 일치하는 항목이 있는지 확인**
    3. **있다면 그 카드(파이어볼)가 발동. 이 경우 필드가 불필드가 아니면 파이어볼 발동 안함.**

## 최적화 구조 제안

런타임에서 카드 사용시마다 `CardSO` 전체를 탐색하는 대신, 게임 **초기화 시점에 캐싱된 딕셔너리를 만들면 성능 문제 해결**

예시)

```csharp

Dictionary<ComboKey, CardSO> comboLookup;

struct ComboKey {
    public string element;
    public string active1;
    public string active2;
    public string field;

    public override bool Equals(...) {...}

}
```

> 
> 
> `인게임 조합 시`는 이 딕셔너리에서 빠르게 `O(1)`로 결과 카드SO를 가져옵니다.
>

### (2) 조합 실패 시: `ComboFallbackSO`

- 조합식이 존재하지 않을 경우, 다음 4가지 결과 중 하나가 **확률 기반으로 발동**됩니다:

| 실패 결과 유형 | 설명 |
| --- | --- |
| 아무 일도 없음 | 카드가 소모되고 아무 효과도 발생하지 않음 |
| 패널티 발동 | 플레이어에게 5 ~ 10의 랜덤한 피해 발생 |
| 일부 카드만 발동 | 액티브1 또는 액티브2 중 하나의 기본 효과만 발동 |
| 무작위 효과 발동 | 게임 내 존재하는 모든 카드효과중 무작위 카드로 발동 |
- 이 확률값은 `ComboFallbackSO`로 중앙 관리되며, 유물 등으로 동적으로 변경될 수 있습니다.

```csharp

// 예시 값

triggerPenaltyChance = 0.3f
triggerPartialChance = 0.3f
triggerRandomChance = 0.1f

```

# ⚔️ Ⅳ. 전투 시스템 상세 정의

전투 시스템은 플레이어가 전략적 사고와 신중한 선택을 하도록 설계됩니다.

---

## 📌 1. 전투 진행 흐름 개요

전투는 다음과 같은 기본 흐름을 가집니다.

```

① 층 진입 즉시 플레이어 턴 시작 (카드 드로우)
② 플레이어 턴 (카드 사용, 마나 사용하여 추가 드로우 등)
③ 플레이어 턴 종료 → 몬스터 턴 시작
④ 몬스터 이동 및 공격 패턴 수행
⑤ 몬스터 턴 종료 → 플레이어 턴 재개
⑥ 모든 몬스터 또는 플레이어의 체력이 0이 될 때까지 반복
⑦ 전투 종료 시 보상 획득 후 즉시 다음 층 이동
```

---

## 📌 2. 플레이어 턴 상세 흐름

### (1) 카드 드로우 시스템

- 턴 시작 시 기본적으로 **최대 5장까지** 카드 드로우
    - 유물 등 효과로 최대 소유 카드 수 증가 가능
- 드로우할 카드가 없으면, 남은 카드만 드로우
- 카드 사용 후 [임시무덤]으로 이동
- 턴 종료시 보유중인 카드들과 임시무덤의 카드들 전부 카드덱으로 되돌리고 셔플한다.

### (2) 마나 시스템 (상세)

- **초기 마나**: 전투 시작 시 30마나로 시작
- **마나 사용**: 카드 추가 드로우에 마나 소모
- **마나 회복**: 매 턴 시작 시 자동으로 **10 마나 회복**
- **마나 추가 드로우**: 추가 카드 드로우 가능(소모 마나 10→20→30 증가)
    - 턴 종료 후 다시 소모마나가 10 마나부터 시작
- **마나 최대치**: 유물 등 효과로 최대 마나량 및 마나 회복량 증가 가능

### (3) 카드 사용 방식

- 하단 카드 슬롯에 카드(최대 3장)를 놓고 「사용」 버튼으로 발동
- 「사용」 버튼 클릭과 턴 종료는 별개로 동작하여 여러 번 카드 사용 가능
- 카드 효과 발동 후 카드는 임시무덤으로 이동
- 카드를 사용하지 않고 턴 종료 가능

---

## 📌 3. 몬스터 턴 상세 흐름

### (1) 몬스터 행동 순서

- 항상 왼쪽(플레이어 쪽)에 가까운 몬스터부터 순서대로 행동
- 모든 몬스터는 반드시 **이동 후 공격** 진행

### (2) 몬스터 이동 패턴 및 위치 규칙

- 몬스터는 필드 오른쪽 끝에서 시작
- 한 칸당 몬스터 1마리만 위치 가능
- 이동 규칙 예시:
    - **기본 패턴**: 왼쪽으로 한 칸씩 이동
    - **특수 패턴**: 두 칸 이동, 플레이어 옆으로 바로 이동 등
- 다른 몬스터 또는 오브젝트가 위치한 칸으로는 이동 불가
    - 이동 불가 시 가장 가까운 빈 칸으로 이동 (건너뛰기 불가)
    - 빈칸이 없을경우 이동하지 않고 공격패턴 진행

### (3) 몬스터 공격 규칙

- **근거리 몬스터**
    - 플레이어 바로 옆(2번 칸)에서만 공격 가능
- **원거리 몬스터**
    - 몬스터별 공격 사정거리 내 플레이어가 있으면 공격 가능
    - 공격 범위는 몬스터 정보에 사전 정의됨

---

## 📌 4. 필드 구조 및 중립 오브젝트

### (1) 필드 구조

- **10칸 횡스크롤 구조**
- 플레이어는 왼쪽 첫 번째 칸(1번)에 위치 고정
- 몬스터들은 오른쪽에서 등장하여 왼쪽으로 이동하며 플레이어 공격

| 칸 번호 | 예시 상황 |
| --- | --- |
| 1번칸 | 플레이어 (고정) |
| 2번칸 | 빈 칸 또는 근접 몬스터 |
| 3번칸 | 중립 오브젝트 (예: 폭탄상자 등) |
| 4~10번칸 | 몬스터 위치 |

### (2) 중립 오브젝트 (예시: 폭탄상자)

- 특정 칸에 위치하여 몬스터 이동을 막거나 전술적 활용 가능
- 체력 보유하며 파괴 시 특정 효과 발동 (적 전체 피해, 주변 N칸 피해 등)
- 전투 시작 시 미리 배치됨 (개발 시 배틀 구성에 설정 가능)

---

## 📌 5. 보스 몬스터 전투 메커니즘

### (1) 특수 사이즈 및 공격 판정

- 보스 몬스터는 2칸 이상을 차지할 수 있음
- 범위 공격(앞의 N칸 공격 등)은 보스의 칸 수만큼 다중 히트
- 플레이어는 칸 위치를 고려하여 전략적으로 공격 가능

### (2) 카드 강제 삽입 기믹

- 보스 몬스터는 특정 패턴으로 턴 시작시 플레이어의 카드 슬롯에 카드를 강제로 넣을 수 있음
    - 예: “사용시 본인에게 5의 피해를 줍니다”등의 효과를 갖는 "자해" 카드 강제 삽입
- 플레이어는 카드 사용 또는 턴 종료로 대응 가능
    - 사용 시 강제 카드 포함된 조합식 발동
    - 미사용 후 턴 종료 시 효과 미발동 (선택적 대응)
- 특정 조합식으로 아예 새로운 카드로 만들어 대응 가능
    - 예: “풀” 속성 카드 + “자해”카드 조합 사용시 “회복” 이라는 카드 발동

### (3) 특정 몬스터 혹은 오브젝트 소환

- 보스 몬스터는 특정 오브젝트 (폭탄상자, 포션상자 등) 혹은 특정 몬스터들을 소환할 수 있다.

### (4) 동시 처치 기믹

- 특정 보스몬스터는 여러마리로 이루어져있고, 한 턴 내에 반드시 동시에 처치해야 몬스터가 최종 사망한다.
- 만약 보스몬스터가 슬라임이라고 하고, 3마리의 슬라임으로 구성됐다면, 플레이어가 한 턴 내에 여러번의 카드 사용을 통해서 한번에 모든 슬라임을 한턴내에 처치하지 않으면, 다음 몬스터 턴에서 다시 3마리가 될때까지 늘어난다.

---

## 📌 6. 전투 설계 및 관리 시스템

### (1) 배틀 구성 관리 방식

- 모든 배틀은 BattleSO라는 **Scriptable Object**로 관리
- 배틀 시작 시 자동으로 Scriptable Object에서 설정된 값 로드

| 관리 요소 | 상세 설명 |
| --- | --- |
| 몬스터 종류 및 수량 | 등장 몬스터 및 위치 미리 설정 |
| 몬스터 시작 위치 | 몬스터가 시작할 칸 번호 설정 |
| 중립 오브젝트 배치 | 특정 오브젝트 배치 칸 번호 지정 |
| 필드 기본 속성 | 시작 필드 속성 설정 (없음 or 특정 속성) |
| 보상 골드 | 전투 종료시 획득할 골드 |

### (2) 유지보수 및 확장 용이성

- 배틀 관리 시스템은 데이터 중심으로 관리
- 추가 몬스터, 중립 오브젝트, 보스 패턴 등 확장 용이
- 게임 난이도 조절을 위한 유연한 수정 가능

### (3) **층별 전투 풀 및 보상 매핑 시스템**

- 각 층은 **BattleStageSO** 라는 Scriptable Object로 정의되며, 해당 층에서 등장 가능한 전투와 보상 구성을 매핑합니다.
- 이를 통해 **같은 층에서도 다양한 전투와 보상 구성이 등장할 수 있어 리플레이성과 콘텐츠 다양성 확보**가 가능합니다.

| 항목명 | 설명 |
| --- | --- |
| 층 번호 | 이 설정이 적용되는 게임 층 번호 |
| 등장 가능 배틀 목록 | 해당 층에서 등장할 수 있는 BattleSO 리스트 |
| 배틀 등장 확률 | 각 배틀의 등장 확률을 비율로 설정 가능 |
| 보상 풀 설정 | 전투 종료 시 등장할 수 있는 보상의 유형 및 풀 (카드, 유물 등) |

# 🎖️ Ⅴ. 유물 시스템 상세 정의

『메글린』에서 유물 시스템은 플레이어의 전략적 선택과 장기적인 게임 플레이의 다양성을 높이기 위한 핵심 시스템입니다.

---

## 📌 1. 유물의 개념과 특징

유물은 플레이어가 한 회차를 진행하는 동안 영구적인 추가 효과를 부여받는 아이템입니다. 전투, 덱 관리, 경제(골드 획득 및 소비), 마나 관리 등 게임 내 모든 요소와 밀접한 관련이 있습니다.

| 유물 특징 | 설명 |
| --- | --- |
| 영구적 효과 | 획득 시 회차 내내 영구적으로 적용됩니다. |
| 중첩 효과 가능성 | 여러 유물의 효과는 중복 적용될 수 있습니다. |
| 다양한 획득 방식 | 전투 보상, 상점 구매, 이벤트 등 다양한 방법으로 획득 가능 |
| 전략적 선택 필수 | 제한된 선택지 중 한 가지를 선택하여 전략적으로 획득합니다. |

---

## 📌 2. 유물의 종류와 획득 방법

유물은 다음 두 가지 유형으로 구분됩니다:

### (1) 일반 유물 (Common Relic)

- 비교적 자주 등장하고 일반 전투 보상, 엘리트 전투 보상, 상점에서 획득 가능
- 효과는 다양하지만 상대적으로 약하거나 기본적 효과를 부여함

### (2) 보스 유물 (Boss Relic)

- 오직 보스 전투(10층, 20층 등) 보상에서만 등장
- 효과가 매우 강력하며, 전략적 플레이에 중대한 영향을 줌
- 상점에서 절대 등장하지 않음

---

## 📌 3. 유물 획득 상황과 방식

| 획득 방법 | 등장 유물 종류 | 등장 수량 | 선택 및 획득 규칙 |
| --- | --- | --- | --- |
| 일반층 전투 | 등장하지 않음 | 없음 | 유물 대신 카드와 골드 제공 |
| 엘리트층 전투 | 일반 유물 | 랜덤 3종 제시 | 3개 중 플레이어가 1개 선택 |
| 보스층 전투 | 보스 유물(1종) + 일반 유물(2종) | 랜덤 3종 제시 | 3개 중 플레이어가 1개 선택 |
| 상점 구매 | 일반 유물 | 랜덤 종류 | 골드를 소모해 구매 가능 |
| 이벤트 | 일반 또는 보스 유물 | 이벤트에 따라 다름 | 선택지에 따라 획득 가능성 존재 |

---

## 📌 4. 유물 효과 유형 및 예시

유물 효과는 게임 내 플레이어 상태, 카드 덱 운영, 전투 보상 등 다양한 방면에 적용될 수 있습니다.

패널티 효과를 지니는 유물도 존재합니다.

효과를 여러개 지닌 유물도 존재합니다. 예를들어 불 속성 카드의 데미지를 증가시키지만, 다른 속성 카드의 데미지를 감소.

| 효과 카테고리 | 유물 효과 예시 | 비고 및 설명 |
| --- | --- | --- |
| 전투 보상 증가 | 전투 종료 시 획득 골드 20% 증가 | 경제적 성장 도움 |
| 덱 관리 강화 | 카드 최대 보유 한도 +1 증가 | 턴마다 보유 가능한 카드 수 증가 |
| 필드 효과 | 전투 시작 시 항상 불 속성 필드 부여 | 특정 카드 조합과 시너지 가능 |
| 마나 관리 강화 | 최대 마나 +10 증가 | 카드 활용의 폭을 증가시킴 |
| 마나 회복 증가 | 턴 시작 시 마나 회복량 +5 증가 | 카드 사용 빈도 증가 |
| 체력 관리 | 전투 시작 시 최대 체력의 10% 회복 | 장기적인 층 공략에 도움 |
| 카드 강화 | 특정 속성 카드의 데미지 15% 증가 | 특정 속성 위주의 전략 가능 |
| 카드 약화 | 특정 속성 카드의 데미지 15% 감소 | 패널티 효과 |
| 경제성 강화 | 상점에서의 구매 비용 10% 할인 | 상점 이용 효율 극대화 |
| 경제성 약화 | 상점에서의 구매 비용 10% 증가 | 패널티 효과 |
- 실제 게임에서는 위와 같은 효과를 가진 다양한 유물을 개발 및 제공할 수 있습니다.
- 효과는 서로 중복될 수 있으며 전략적으로 시너지 효과를 노릴 수 있습니다.

---

## 📌 5. 유물 관리 및 데이터 시스템 (Scriptable Object)

유물은 카드, 전투와 동일하게 **Scriptable Object**로 관리되어 쉽게 유지보수 및 확장 가능합니다.

### 유물 Scriptable Object 관리 구조

| 데이터 항목 | 설명 | 예시 |
| --- | --- | --- |
| 유물 이름 | 유물의 고유 이름 | 골드 망토 |
| 유물 타입 | 일반 / 보스 유물 구분 | 일반 |
| 유물 효과 | 구체적인 유물 효과 정보 | 획득 골드 +20%, 마나 최대량 -10 |
| 중첩 가능 여부 | 동일 효과의 유물 중첩 적용 여부 | O |
| 유물 이미지 | 유물 아이콘 및 UI 이미지 | gold_cloak_icon |
| 유물 설명 텍스트 | UI상 표시되는 상세한 설명 텍스트 | "모든 전투에서 획득하는 골드가 20% 증가합니다." |
| 유물 가격 | 상점에서 판매하는 유물 가격 | 300 |
- 이 방식은 신규 유물 추가 및 효과 변경 시 코드 변경 없이 데이터만 수정하여 반영 가능합니다.

---

## 📌 6. 시스템 확장성과 유지보수 용이성

- 새로운 유물 추가 및 기존 유물 효과 변경이 매우 용이한 구조입니다.
- 유물의 효과가 전투, 카드, 경제 등과 연관되어 있기 때문에 데이터 중심 설계를 통해 향후 유연하게 확장할 수 있습니다.
- 신규 업데이트 시에도 게임 구조 및 코드를 크게 변경하지 않고 콘텐츠 추가 및 관리 가능합니다.

# 💰 Ⅵ. 보상 및 상점 시스템 상세 정의

『메글린』에서 보상 및 상점 시스템은 플레이어의 성장 동기와 전략적 선택을 극대화하기 위한 핵심 시스템입니다. 보상을 통해 플레이어가 층을 오르며 성장할 수 있도록 지원하고, 상점을 통해 전략적 의사결정을 돕습니다.

---

## 📌 1. 전투 보상 시스템

전투 보상은 층의 유형과 난이도에 따라 다르게 지급됩니다.

### (1) 일반층 전투 보상

- 일반 전투는 플레이어의 덱을 강화하는 기본 보상을 제공합니다.

| 보상 항목 | 보상 수량 | 지급 방식 | 비고 |
| --- | --- | --- | --- |
| 골드 | 소량 | 전투 종료 시 자동 획득 | 일정 바운더리 내에서 랜덤 지급 |
| 카드 | 랜덤 3종 중 1개 | 플레이어가 원하는 1장을 선택하여 획득 | 선택 지급 |

---

### (2) 엘리트층 전투 보상

- 엘리트 전투는 일반 전투보다 강력한 몬스터와의 전투로, 더욱 가치 있는 보상을 제공합니다.

| 보상 항목 | 보상 수량 | 지급 방식 | 비고 |
| --- | --- | --- | --- |
| 골드 | 중간량(일반층 대비 많음) | 전투 종료 시 자동 획득 | 일정 바운더리 내에서 랜덤 지급 |
| 유물 | 랜덤 3종 중 1개 | 플레이어가 원하는 1종을 선택하여 획득 | 선택 지급 |

---

### (3) 보스층 전투 보상

- 보스 전투 보상은 매우 가치가 높으며, 전략적으로 중요한 보스 유물을 포함합니다.

| 보상 항목 | 보상 수량 | 지급 방식 | 비고 |
| --- | --- | --- | --- |
| 골드 | 대량(엘리트층 대비 많음) | 전투 종료 시 자동 획득 | 일정 바운더리 내에서 랜덤 지급 |

### 상점에서 제공하는 항목:

| 카드 제거 | 플레이어 덱에서 카드 1장 영구히 제거 | ✅ (골드 소모) | 덱 최적화 및 관리 |
| 유물 구매 | 일반 유물을 골드를 지불하여 구매 가능 | ✅ (골드 소모) | 전략적 효과 강화 |
| 체력 회복 | 플레이어의 체력을 일정량 회복 가능 | ✅ (골드 소모) | 장기적 생존률 증가 |

전투 보상 및 상점 시스템 또한 **Unity Scriptable Object**로 관리됩니다.

### (1) 보상 관리 Scriptable Object 구조

| 항목명 | 설명 | 예시 값 |

## 📌 1. 플레이어 상태 관리

## 📌 2. 카드 덱 관리 시스템

카드 덱 관리는 플레이어가 보유한 모든 카드를 관리하고, 전투 중 드로우를 원활하게 수행할 수 있도록 명확한 구조를 가집니다.

### (1) 카드 덱 기본 구조

플레이어는 다음과 같은 카드 관련 영역을 가집니다:

| 카드 영역 | 설명 |
| --- | --- |
| 메인 덱 | 플레이어가 전투 시 카드 드로우를 하는 기본 카드 묶음 |
| 임시 무덤 | 사용된 카드가 임시로 위치하는 영역 (턴 종료 후 메인 덱으로 이동) |

### (2) 카드 덱 순환 흐름

전투 중 카드 덱 순환은 다음과 같은 구조를 가집니다:

```

턴 시작 (최대 5장까지 드로우) → 카드 사용(임시 무덤으로 이동)
→ 추가 드로우 (마나 사용, 비용 증가 10→20→30)
→ 턴 종료 (임시 무덤 카드 및 가지고있는 카드 전부 메인 덱으로 이동 후 셔플)
```

---

## 📌 3. 카드 드로우 관리 및 제한 규칙

- 기본적으로 플레이어는 한 턴당 최대 **5장**의 카드만 보유할 수 있습니다.
- **유물 효과로 최대 소유 카드 수량**을 증가시킬 수 있습니다.
- 추가 카드 드로우 시, 소모 마나 비용이 **10 → 20 → 30** 순으로 증가하며, 턴 종료 후 다시 **10**으로 초기화됩니다.
- 더 이상 덱에 카드가 없을 시 남은 카드만 드로우됩니다.

---

## 📌 4. 카드 사용 후 처리 시스템 (임시 무덤)

- 사용한 카드는 **[임시 무덤]**이라는 별도의 임시 영역으로 이동합니다.
- 턴 종료 후, 임시 무덤에 있는 모든 카드는 메인 덱으로 복귀되며, 덱 전체를 다시 셔플합니다.
- 이를 통해 전투 중 카드 사용 후 빠른 순환과 덱 관리가 가능합니다.

## 📌 5. 이펙트 및 사운드 관리

- 모든 이펙트는 유니티의 **Particle System**을 이용하여 구현하고 관리합니다.
- 사운드 효과 및 배경 음악은 AudioManager를 별도로 구현하여 쉽게 관리하고 확장할 수 있도록 설계합니다.
- 카드 사용, 전투 효과 등 각 요소의 이펙트와 사운드는 Scriptable Object 내에서 직접 연결되어 관리됩니다.

---

## 📌 6. 코드 작성 규칙 및 설계 기준

### (1) 코드 구조 및 네이밍 규칙

- 클래스 이름은 PascalCase 사용 (`BattleManager`)
- 변수와 함수 이름은 camelCase 사용 (`playerHealth`, `drawCard()`)
- 상수는 대문자와 언더바로 구성 (`MAX_CARDS`)
- 모든 클래스와 메소드는 명확한 역할과 책임을 가짐 (Single Responsibility 원칙 준수)

### (2) 주석과 코드 가독성

- 메소드와 주요 로직에는 주석 필수 작성
- 코드 작성 시 간결성 유지, 지나친 중첩 및 복잡한 로직은 지양
- 명확한 이름의 변수와 함수로 코드의 가독성 극대화

### (3) 이벤트 및 델리게이트 활용

- 시스템 간의 유연한 통신을 위해 이벤트 및 델리게이트 적극 활용
- 이벤트 기반 시스템 설계를 통해 시스템 간 종속성을 최소화

## 📌 7. 성능 및 최적화 고려 사항

- UI 및 이펙트의 성능 최적화 (불필요한 Instantiate 제거, Object Pooling 활용)
- Scriptable Object를 통한 데이터 접근 시 메모리 효율성 유지
- 주기적으로 프로파일링하여 프레임 저하 요소 파악 및 최적화

---

## 📌 8. 확장성 및 유지보수 용이성 보장

- 신규 콘텐츠(카드, 유물, 몬스터 등)의 추가가 코드 변경 없이 Scriptable Object 데이터만으로 가능하도록 설계
- 시스템 모듈 간 결합도를 최소화하여 개별 시스템의 수정 및 확장 용이성 보장
- 새로운 전투 메커니즘, 이벤트 시스템 추가 시 코드의 최소한 변경으로 적용 가능하도록 유연한 구조 유지
